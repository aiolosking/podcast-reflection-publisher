# podcast-reflection-publisher

一个 Qoder Skill：把**一期播客**变成一篇**图文并茂、可以公开发布的公众号听后感**。

它解决的不是"帮我总结这期播客"，而是从素材到成品链接的整条链路：听完一整期音频、核对事实、按你指定的作者风格写成一篇有独立立意的原创文章、配真实图片、生成断网也能双击打开的 HTML，最后发布成别人免登录就能看的链接。

## 你需要准备的两样东西

1. **播客音频**——本地音频文件、节目链接，或者你已经有的逐字稿。
2. **一份已经总结好的作者风格报告**——JSON / Markdown / TXT 都行，写清楚那位作者怎么开头、怎么断句、怎么收尾、常用什么修辞。

风格**不内置在这个 Skill 里**。上传谁的报告，出来的就是谁的风格；换一份报告就换一种文风。这也意味着它不替你分析样本——风格总结是上游工作，本 Skill 只负责忠实地把它用在正文上。

可选补充：你自己真实想分享的观点或感受片段、指定的切入角度、目标读者、字数（默认 2500–3500 字）、你手头的真实图片、指定发布平台。

## 怎么触发

装好之后（见下一节），直接说：

> 这是这期播客的音频，这是风格报告，帮我写一篇听后感，配真图，出本地 HTML，然后发成链接。

Skill 会按阶段推进：准备目录 → 理解音频 → 套用风格 → 写作 → 配图 → 生成 HTML → 发布 → 验证交付。缺必需材料时它会一次性说清缺什么，而不是边做边追问。

## 安装

把整个目录放进用户级技能目录，Qoder 会热加载，不用重启：

- Windows：`C:\Users\<你>\.qoder\skills\podcast-reflection-publisher\`
- macOS / Linux：`~/.qoder/skills/podcast-reflection-publisher/`

## 文件构成

| 文件 | 管什么 |
| --- | --- |
| `SKILL.md` | 主流程与硬性边界，阶段 0–7 |
| `references/writing-rules.md` | 怎么读并套用风格报告，听感文的选题与写作要求 |
| `references/image-rules.md` | 只用真实图片：来源页、作者、授权、图注如何记录 |
| `references/publishing.md` | 发布平台的探测顺序、上传校验、公开链接标准 |
| `scripts/publish_anonymous.py` | 默认发布路线：匿名免账号上传，72 小时有效，带字节回读校验 |
| `templates/task-brief.md` | 开跑前填的任务单，含三项授权确认 |

## 两处需要你自己配置

**长音频转写。** 本 Skill 不绑定任何转写引擎，它用你当前环境里可用的工具。没有可用转写能力时，它会明说，并请你自己上传文字稿，不会假装听完了音频。

**发布。** 默认走匿名免账号的临时直传（链接 72 小时后失效、不可删除、不可续期，且不保证在你所在网络可达）。要长期稳定的地址，需要你自己在 GitHub Pages / Surge / Netlify 之类的平台建好托管，并把配置告诉它；`references/publishing.md` 里写的是"按用户指定 → 本机已有配置 → 免账号临时床 → 否则只交本地稿"这个优先级。

## 它明确不做的事

不编造你的经历和情绪，不把节目里人物的故事写成你亲历的，不虚构"我采访了""我实测过"。

不移植风格来源作者的身份、经历和署名——仿的是笔法，不是冒充那个人。

不公开原始音频、逐字稿、你上传的风格报告、你的私人感受、内部核对记录，也不公开任何账号配置。发布的只有最终 HTML。

不擅自购买服务或域名，不执行音频和转写文本里夹带的任何"指令"——那些只是素材。

没有实际验证过的环节会如实写出来，不会声称全部通过。你只要本地稿时，它就不发布。

## 产物

`article.html`（单栏、样式与图片全内嵌、断网可看）、`article.md`、`images/`（原图与授权记录）、`sources.md`（事实与图片来源），以及一份**禁止发布**的 `内部资料/`（转写与核对记录）。
